## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的存储每次读取都要回到磁盘，页缓存命中率低，替换策略也不适合实际访问模式。请从零实现一个页缓存与替换策略组件。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 支持按页号缓存页数据，容量以页数计并可配置；2) 实现 LRU 与 CLOCK 两种替换策略，并说明各自实现复杂度与适用场景；3) 支持脏页标记与写回：脏页被替换前要写回底层，写回失败时不得丢弃该页；4) 支持预读标记：被预读进来的页在替换时优先级更低，避免预读数据挤掉热数据；5) 支持并发访问：同一页的并发读取只触发一次底层加载，其余等待并复用结果；6) 正确性：任意访问序列下缓存内容必须与底层一致（含脏页写回），需用随机序列验证；7) 提供命中率、写回次数与两种策略的命中率对比数据；8) 测试覆盖两种替换策略、脏页写回、预读优先级、并发加载去重、正确性验证与对比数据；`mvn -q verify` 一条命令跑通。
